# 【要件定義書】バーコード対戦スマホアプリ（プロトタイプ版 PRD）

## 1. プロジェクト概要

### 1.1 目的・背景
身の回りのJANバーコードをスマホカメラでスキャンし、数値情報から決定論的に生成されたキャラクターを用いて、4桁のルームコード経由で友達同士で手軽にコマンド対戦ができるプロトタイプアプリを構築する。

### 1.2 運用・検証方針
- **主要ターゲット**: 小中学生を中心とする試遊モニター（20名程度）および仲間内
- **対象プラットフォーム**: iOS / Android / Web (Cross-Platform)
- **課金要素**: **完全無し**（全機能無料でプレイ可能）
- **インフラ前提**: 運用費完全ゼロ円の軽量リアルタイム通信インフラ
- **開発方針**: 演出の気持ちよさと対戦の戦略性を優先した最小実用プロダクト（MVP）

---

## 2. システム構成・技術スタック提案

- **フロントエンド**: Cross-Platform (Unity / Flutter / Modern Web API)
- **バーコード読取**: Google ML Kit / ZXing ライブラリ（スマホ内蔵カメラ利用）
- **リアルタイム通信**: WebSocket / Firebase Realtime Database (無料枠活用)
- **ローカルストレージ**: SQLite / SharedPreferences / IndexedDB (スキャン済みキャラ図鑑の端末保存)

## 4. データ構造・計算式仕様

### 4.1 JAN13コードからのステータス＆グラフィック算出式
JAN13コード `d1 d2 d3 d4 d5 d6 d7 d8 d9 d10 d11 d12 d13` を用いて算出：

- **HP (体力)**: $1000 + (d_{10} \times 100) + (d_{11} \times 10)$ （範囲: 1000 〜 1990）
- **ATK (攻撃力)**: $100 + (d_8 \times 20) + d_9$ （範囲: 100 〜 289）
- **DEF (防御力)**: $50 + (d_6 \times 10) + d_7$ （範囲: 50 〜 149）
- **SPD (素早さ)**: $10 + (d_4 \times 5) + d_5$ （範囲: 10 〜 105）
- **属性**: $d_{13} \pmod 3 \implies 0:\text{火}, 1:\text{水}, 2:\text{木}$
- **レアリティ**: $d_1 \times d_2 \times d_3$ の値を判定値とし、一定閾値以上を SSR / SR / R / N に分類。

- **キャラクター名の生成アルゴリズム (ワード組み合わせ)**:
  JANコードのハッシュ値から3つのワードリストのインデックスを決定論的に抽出：
  - `称号1`: 「爆炎の」「蒼海の」「疾風の」「伝説の」「すーぱー」「はらぺこ」「無敵の」「きらめく」等 (20種類)
  - `ベース名`: 「ドラゴン」「ゴーレム」「ナイト」「フェニックス」「タイガー」「スライム」「ベア」「ロボ」等 (20種類)
  - `称号2`: 「バトラー」「キング」「マスター」「ヒーロー」「ビースト」「ガード」等 (10種類)
  - **名前合成**: `[称号1] + [ベース名] + [称号2]` （例: $20 \times 20 \times 10 = 4,000$ 通りの組み合わせ）

- **グラフィック生成アルゴリズム (パーツ・カラーレイヤー合成)**:
  無限のバーコードに対応するため、限定されたベースアセットから動的に合成：
  - `ベーススプライト`: 20種類のモンスターシルエット/イラスト（JANハッシュ $H_1 \pmod{20}$）
  - `カラーシフト`: 属性（火:赤/橙、水:青/シアン、木:緑/黄緑）に応じたシェーダー/CSSカラーシフト
  - `装飾エフェクト`: レアリティに応じたオーラ・フレーム（N:なし, R:オーラ, SR:雷光, SSR:金色の輝きと翼）
  - **結果**: 20種ベース × 3属性カラー × 4レアリティエフェクト ＝ **240通りのバリエーション表現**を動的生成。
- **カード種別判定**: スキャン時に一定条件（JANハッシュ等）を満たした場合、キャラクターではなく「ステータス強化・回復効果を持つ強化アイテムカード」をドロップ。

### 4.2 行動順判定・バトル計算式
- **行動順判定式**:
  $$\text{行動判定値} = \text{SPD} \times \text{乱数}(0.85 \sim 1.15)$$
  毎ターン判定値を計算し、値が大きい順に行動する（SPDが高くても低確率で後攻になるランダム性を持たせる）。

- **通常攻撃＆ダメージ乱数**:
  - **命中判定**: 8%の一定確率で攻撃が「ミス (MISS)」となりダメージ0（演出とともに表示）。
  - **ダメージ計算**: 
    $$\text{Damage} = (\text{ATK} - \text{敵DEF}) \times \text{属性補正 (1.0 or 1.5)} \times \text{乱数}(0.90 \sim 1.10)$$
    (最低ダメージ: 1。毎回若干の振れ幅を持たせる)

- **SPゲージ（必殺技用ゲージ）の定義**:
  - バトル中に蓄積される100%制の共通ゲージ。通常攻撃実行時（+25%）、被ダメージ時（被ダメ量に応じて+10%〜20%）、ガード実行時（+30%）に増加。

- **必殺技 (Skill)**:
  - **発動条件**: SPゲージ100%消費。
  - **特徴**: キャラクター固有の特殊技（高威力属性攻撃、バフ/デバフ等）。SPゲージが溜まれば1バトル中に何度でも使用可能。

- **一発逆転チャンス (QTE)**:
  - **発動条件**: **SPゲージ不問・1バトル1回のみ使用可能**な全キャラ共通の切り札コマンド。
  - **特徴（必殺技との違い）**: タイミング合わせミニゲーム（QTE）が発生。成功すれば「ダメージ2.5倍の大打撃」、失敗すれば「ミス/小ダメージ」となるハイリスク・ハイリターンのプレイヤー操作介入要素。

- **ガード**:
  - そのターンの被ダメージ50%カット ＋ SPゲージ増加（+30%）。

## 5. 画面一覧・画面遷移

```
[ホーム画面] ──┬──> [スキャン画面] ──> [スキャン結果（入手）画面]
             │
             ├──> [図鑑・デッキ編成画面]
             │
             └──> [対戦ロビー画面]
                       ├──> [ルーム作成 (ホスト)] ──┐
                       │                            ├──> [バトル画面] ──> [リザルト画面]
                       └──> [ルーム参加 (ゲスト)] ──┘
```

### 主要画面要件
1. **ホーム画面**: 「スキャン」「ずかん」「たいせん」の3大ボタン配置。
2. **対戦ロビー画面**: 「へやをつくる」「へやにはいる」選択。
3. **バトル画面**: 自分・相手のHP、属性、ステータス、コマンドボタン（こうげき/ひっさつ/ガード/ぎゃくてん）。
4. **リザルト画面**: WIN/LOSE表示、対戦結果ログ、ロビー復帰ボタン。

---

## 6. 非機能要件 (Non-Functional Requirements)

- **パフォーマンス (レスポンス性)**: ルームコード接続からバトル開始までの同期時間を **2秒以内** とする。
- **操作性・アクセシビリティ**:
  - 小中学生でも直感的に操作できるよう、テキストを最小限にし、大きなアイコンとひらがな表記（ふりがな付き）を中心にする。
- **端末負荷・フレームレート**:
  - 旧世代スマホ（iPhone 8 / Android 8相当以上）で **30fps以上** のスムーズ動作を実現。
- **運用コスト**:
  - サーバー運用コスト完全ゼロ円（Free TierまたはP2P同期）。
