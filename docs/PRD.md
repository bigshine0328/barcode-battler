## 1. プロジェクト概要 & コアバリュー

### 1.1 目的・背景
日常に溢れる商品のJANバーコード（13桁/8桁）をスマートフォンのカメラや手動入力でスキャンし、バーコード数値から決定論的に全20系統のモンスターまたは8種類の強化アイテムを生成。
「3体チーム ＋ 3種アイテム」のデッキを編成し、WebRTC P2P通信（Host Authorityモデル）によりリアルタイム対戦を楽しめるブラウザ完結型レトロフューチャー・カードバトルWebアプリケーション。
P2P対戦を通じて経験値（EXP）を獲得し、**最大レベル100（Lv.100）** までキャラクターを育成・強化できる本格RPG成長システムを搭載する。

### 1.2 対象プラットフォーム
- **Web / Mobile Browser (PWA対応)**: iOS Safari (iOS 15+), Android Chrome (Android 10+), PC Chrome/Edge/Safari。

### 1.3 主要ターゲット & コア体験
- **ターゲット**: バーコードバトラー世代、レトロゲームファン、カジュアル対戦ゲーム愛好者。
- **コア体験**: 身近なバーコードから強いモンスターを発見するワクワク感、属性相性・アイテム選択・キャラクター交代を駆使した3〜5ターンのハイスピード頭脳対戦、そして対戦によるキャラクター育成。

---

## 2. システム構成・技術スタック

- **フロントエンド**: HTML5 / CSS3 / Vanilla ES6+ JavaScript（単一バンドル `src/js/bundle.js`）
- **P2P通信**: WebRTC / PeerJS (Host Authority パターン ＋ STUN 5重冗長化 ＋ リトライハンドシェイク)
- **永続化**: ブラウザ LocalStorage (100枚保存・デッキ3スロット保存・カスケード保護・Lv/EXPマイグレーション)
- **バーコードスキャン**: WebRTC `getUserMedia` ＋ Shape Detection API (`BarcodeDetector`) ＋ 手動フォールバック

## 3. 機能要件 (Functional Requirements) & 受け入れ基準 (DoD)

### 【F-01】バーコードスキャン & 決定論的マルチバリエーション生成
- **機能概要**:
  - 13桁/8桁のJANバーコードをハッシュ化し、キャラクター（80%）またはアイテム（20%）を決定論的（同一コードからは常に同一パラメータ）に生成する。
- **全20種族定義**:
  1. `ドラゴン` (鋭い角と巨大な翼)
  2. `ゴーレム` (重厚な岩石ボディとツインアイ)
  3. `ナイト` (聖騎士の盾と兜)
  4. `フェニックス` (炎の翼と尾羽)
  5. `タイガー` (雷虎の縞模様)
  6. `スライム` (丸みボディと可愛い瞳)
  7. `ベア` (迫力ある凶暴クマ)
  8. `ロボ` (サイバーアンテナとメカアイ)
  9. `ウルフ` (疾風の狼)
  10. `ライオン` (百獣のたてがみ)
  11. `イエティ` (氷雪の怪人)
  12. `グリフォン` (鷲の翼と頭部)
  13. `バトロボ` (重火器武装のバトルドロイド)
  14. `クラーケン` (深海の触手巨大魔獣)
  15. `ペガサス` (天馬の純白の翼)
  16. `キマイラ` (三頭の合成魔獣)
  17. `デーモン` (闇の角と悪魔の翼)
  18. `レヴィアタン` (渦巻く大海蛇)
  19. `ネクロマンサー` (髑髏と魔導フード)
  20. `ファントム` (揺らめく幽霊・霊体)
- **3属性均等決定ロジック & マルチカラーパレット**:
  - **属性決定計算式**: `elements = ["火", "水", "木"]; element = elements[Math.abs(hash) % 3];` （8桁・13桁問わず各33.3%均等分散）
  - 🔥 **火属性**: フレイムレッド (`#FF2200`) / 閃光ゴールド (`#FFFF00`) / ダークマグマ (`#880011`)
  - 💧 **水属性**: アクアブルー (`#0088FF`) / ネオンシアン (`#00FFFF`) / 深海ネイビー (`#002266`)
  - 🌲 **木属性**: エメラルドグリーン (`#00AA44`) / ライムイエロー (`#FFFF33`) / フォレストシャドウ (`#003311`)
- **4段階レアリティ & ステータス補正 & 専用背景演出**:
  - ✨ **SSR (上位 3%)**: 基礎ステータス **$\times 1.50$** / アイテム効果 **$\times 1.50$** / 16芒巨大サンバースト大光槍 ＋ 黄金ルーン魔方陣 ＋ 星屑スパークル ＋ ゴールドパルス
  - 🌟 **SR (上位 12%)**: 基礎ステータス **$\times 1.30$** / アイテム効果 **$\times 1.30$** / 紫のサイバーオーラ ＋ ヘックス（六角形）グリッドパターン
  - 🔷 **R (上位 25%)**: 基礎ステータス **$\times 1.15$** / アイテム効果 **$\times 1.15$** / シアンクリスタルリング ＋ エナジー粒子
  - ⚪ **N (残り 60%)**: 基礎ステータス **$\times 1.00$** / アイテム効果 **$\times 1.00$** / ディープネイビー円形ベースプレート ＋ アークティックライン
- **初期生成ステータス**: 生成時のキャラクターは `level: 1, exp: 0` で生成される。
- **受け入れ基準 (DoD)**:
  - [ ] 同一のバーコードを入力した場合、何度実行しても全く同じ名前・種族・属性・レアリティ・ステータスが生成されること。
  - [ ] 8桁バーコードおよび13桁バーコードにおいて、火・水・木の3属性が偏りなく均等（約33.3%ずつ）に出現すること。
  - [ ] レアリティに応じてステータス（HP, ATK, DEF, SPD）およびアイテム効果値が補正倍率通りに強化されること。
  - [ ] 全20種族それぞれに対応した固有のSVGグラフィックが生成されること。

  - [ ] カメラ権限が拒否された場合、エラーダイアログとともに手動入力UIが前面に表示されること。

### 【F-04】図鑑・コレクション管理 & デッキ最優先ソート & 100枚超過時削除選択UI
- **機能概要**:
  - **デッキ採用カード最優先ソート表示**: 図鑑一覧において、デッキにセットされているカード（メインキャラ ➔ サブ1 ➔ サブ2 ➔ アイテム1 ➔ アイテム2 ➔ アイテム3）を未セットカードよりも優先して**リスト最上部（先頭）** にソートして表示する（サブタブ絞り込み時も同様に最優先配置）。
  - **最大100枚保存上限**: 所持カードが100枚に達している状態で新規カードを保存しようとした場合、**「所持上限（100枚）に達しています。入れ替えるカードを選択して削除してください」というカード選択削除モーダルを表示**し、ユーザーが選んだカードを削除した上で新規カードを保存する。
  - **サブタブ絞り込み**: **「すべて」「👾 キャラクター」「💊 アイテム」** の3分類で即座にフィルタリング切り替え。
  - **カード詳細モーダル**: 図鑑カードタップで拡大表示、現在のレベル・EXP進行度バー表示、メモの再編集、カード削除、デッキ各スロットへのセットが可能。
- **受け入れ基準 (DoD)**:
  - [ ] デッキにセットされたキャラクターおよびアイテムが、図鑑画面の最上部（先頭）に優先して表示されること。
  - [ ] 所持カードが100枚の状態で保存を実行した際、削除対象選択モーダルがポップアップし、選択したカードが削除されて新しいカードが正常に保存されること。
  - [ ] 「すべて」「キャラクター」「アイテム」のサブタブを切り替えた際、該当するカードのみがグリッドに表示されること。
  - [ ] カード詳細モーダル内に現在のレベルとEXP進行度バー（例: `EXP: 340 / 500 (68%)`）が正常に表示されること。

### 【F-05】デッキ編成 (3キャラ + 3アイテム枠 & カスケード保護 & 3枚同時ハイライト)
- **機能概要**:
  - **デッキ構成**:
    - **メインキャラ**: 1P/3P対戦の先鋒出撃キャラクター。
    - **サブキャラ 1**: 3Pチーム戦の次鋒キャラクター。
    - **サブキャラ 2**: 3Pチーム戦の大将キャラクター。
    - **アイテム 1**: バトル中に使用可能な強化アイテムスロット1。
    - **アイテム 2**: バトル中に使用可能な強化アイテムスロット2。
    - **アイテム 3**: バトル中に使用可能な強化アイテムスロット3。
  - **3枚同時ハイライト**: デッキにセットされたアイテム1・2・3は、図鑑一覧上で `[💊 アイテム1]`, `[💊 アイテム2]`, `[💊 アイテム3]` の個別バッジが付与され、3枚とも同時にハイライト枠線が表示される。
  - **外枠発光とデッキ選択枠の分離（「✅DECK」リボン廃止）**: レアリティ発光オーラ（SSR黄金、SR紫、R水色）とデッキ選択中の太枠シアンボーダー（`.is-deck-set`）を明確に区別して描画。図鑑一覧における「✅DECK」テキストリボンは廃止し、枠線の色（シアン太枠）およびスロットバッジ（`[⚔️ メイン]`, `[🛡️ サブ1]`等）のみでスマートに識別する。
  - **カスケード解除保護**: デッキにセットされているカードを図鑑から削除した場合、デッキの該当スロットのみが安全に `null` に解除され、他スロットやデータ整合性に影響を与えない。
- **受け入れ基準 (DoD)**:
  - [ ] デッキ編成画面および図鑑詳細モーダルから、3つのアイテムスロットに個別にアイテムをセット・解除できること。
  - [ ] デッキにセットされたカードには「✅DECK」リボンは表示されず、太線シアンボーダーと専用スロットバッジが表示されること。
  - [ ] セット中カードを図鑑から削除した際、デッキの該当スロットのみが安全に解除されること。

### 【F-06】バトル中アイテム選択使用 (全8種アイテム)
- **機能概要**:
  - バトル中に「💊 アイテム」ボタンをタップすると、デッキにセットした3種類のアイテム一覧から未消費のものを選択して発動できる（1バトルにつき各アイテム1回、最大3回）。
  - **全8種アイテム効果一覧**:
    1. `heal`: HP回復 (基礎値 +300 HP)
    2. `buff_atk`: 攻撃力強化 (基礎値 +40 ATK)
    3. `buff_def`: 防御力強化 (基礎値 +40 DEF)
    4. `buff_spd`: 素早さ強化 (基礎値 +40 SPD)
    5. `charge_sp`: SP充填 (SP 100% 満タン)
    6. `bomb`: 固定ダメージ爆弾 (相手に 250 固定ダメージ)
    7. `heal_def`: 複合回復防壁 (HP +200 & DEF +40)
    8. `all_buff`: 全能力ブースト (ATK +30, DEF +30, SPD +30)
- **受け入れ基準 (DoD)**:
  - [ ] バトル画面で「アイテム」ボタンを押した際、セットした3つのアイテム一覧モーダルが表示され、未消費のアイテムを選択して効果を発動できること。
  - [ ] 使用したアイテムは「使用済」として非活性化し、合計3回使用後に「アイテム」ボタン自体がdisabledになること。

### 【F-07】3P対戦キャラクター途中交代（スイッチ）機能
- **機能概要**:
  - 3P対戦時、ターン中のコマンド選択肢に「🔄 こうたい」を追加。
  - 生存している控えキャラクターを選択して交代可能（全滅時は非活性化）。
  - **素早さ（SPD）に基づく被ダメージ判定仕様**:
    - **相手が先攻の場合**: 相手の攻撃が発動し、**交代前のキャラクターがダメージを受ける**（倒れた場合は撃破交代へ移行、耐えきれば予定通り交代）。
    - **自分が先攻の場合**: 先に控えキャラクターへと交代完了し、**交代後の新キャラクターがダメージを受ける**。
  - 各キャラクターのHP・SP・バフ状態は個別に独立して維持・管理される。
- **受け入れ基準 (DoD)**:
  - [ ] 素早さで勝っている状態で交代した場合、先に新キャラクターへと交代が完了し、敵の攻撃を新キャラクターが受けること。
  - [ ] 素早さで負けている状態で交代した場合、敵の先制攻撃を交代前のキャラクターが受け、生存していれば交代が完了すること。

### 【F-08】3P対戦 チームサブカプセルスロット（残数・体力可視化 & 属性色付きドット）
- **機能概要**:
  - 敵・味方の情報バー内にチーム3体のスロット（横並び3分割）を常時表示。
  - **出撃中キャラ**: 黄金枠ハイライト ＋ 属性丸印（火:赤●, 水:青●, 木:緑●） ＋ 残りHP/最大HP ＋ ミニHPバー。
  - **控えキャラ**: 通常枠 ＋ 属性丸印（火:赤●, 水:青●, 木:緑●） ＋ 残りHP/最大HP ＋ ミニHPバー。
  - **戦闘不能キャラ**: 💀アイコン ＋ グレーアウト表示。
  - **完全ノースクロール設計**: 縦スクロール・横スクロールが不要で1画面内に美しく収まるレイアウト。
- **受け入れ基準 (DoD)**:
  - [ ] 3P対戦開始時に敵・味方双方の3体サブスロットが正常に描画され、ダメージや交代に応じてHPバーと枠線がリアルタイムに更新されること。
  - [ ] 画面の縦スクロール・横スクロールが発生せず、全要素がビューポート内に美しく収まること。

### 【F-09】P2P対戦マッチング & Host Authority完全同期 & 切断・逃走時強制終了
- **機能概要**:
  - **ホスト権威モデル**: ホスト側が唯一の審判としてターン計算・ダメージ・勝敗を一括実行し、確定ステート（`STATE_SYNC`）をゲストに配信。双方の端末でHPやSPが1ミリもズレないことを保証。
  - **ホスト主導ルール統一**: ホストが作成した部屋のルール（`1p` または `3p`）を公式ルールとし、ゲストは自動的に同じ人数（1体 vs 1体、または3体 vs 3体）で対戦を開始する。
  - **STUN 5重冗長化 & リトライハンドシェイク**: `stun.l.google.com:19302` 等のSTUNサーバーを明示指定し、ゲストは `START` 受信まで500msおきに再送ポーリングを行うことで、NAT越えとパケットロスを完全防止。
  - **切断・逃走時強制終了 & ロビー自動復帰**: バトル中に対戦相手が「にげる」ボタンを押した際（`ESCAPE` メッセージ送信）や、相手の通信切断（ブラウザ閉じる、回線断絶等）が発生した場合（`close` / `error` イベント検知）、バトルを即座に強制終了して「相手がバトルから離脱したか、通信が切断されました」と通知した上で、対戦ロビー画面（`SCR-05`）へ自動復帰・P2P通信リソースを安全にクリーンアップする。
- **受け入れ基準 (DoD)**:
  - [ ] 2台の端末間で4桁コードを入力し、P2P接続が確立して双方が同一ルール（1Pまたは3P）でバトルを開始できること。
  - [ ] バトル中のHP・SP・勝敗結果がホスト・ゲスト間で100%一致すること。
  - [ ] バトル中に対戦相手が離脱または切断された際、取り残されることなくダイアログが表示されて対戦ロビーへ自動復帰すること。

### 【F-10】レベル（LV）＆ 経験値（EXP）成長システム & 全画面リアルタイム同期
- **機能概要**:
  - **最大レベル**: `Lv.100`（カンスト時は「Lv.MAX」と表示し、以降EXPは蓄積されない）。
  - **必要経験値計算式（累乗カーブ）**:
    $$\text{NextEXP}(LV) = \lfloor 40 \times (LV)^{1.4} \rfloor$$
    - Lv.1 ➔ Lv.2: `40 EXP`
    - Lv.10 ➔ Lv.11: `100 EXP`
    - Lv.30 ➔ Lv.31: `465 EXP`
    - Lv.50 ➔ Lv.51: `965 EXP`
    - Lv.99 ➔ Lv.100: `2,530 EXP`
  - **対戦による経験値獲得ルール**:
    - **P2P対戦 勝利時**: `+100 EXP`
    - **P2P対戦 敗北時**: `+30 EXP`
    - **CPU対戦時**: `0 EXP`（※経験値は一切獲得できない）
  - **3P対戦におけるEXP付与対象ルール (案B)**:
    - **そのバトルで実際に出撃（戦闘参加）したキャラクターにのみ付与**。
    - 出撃しなかった控えキャラクターにはEXPは付与されない（交代を活用したキャラのみ成長）。
    - 1P対戦時は出撃したメインキャラクターに付与。
  - **レベルアップ時のパラメータ成長式 & 全画面即時同期**:
    $$\text{Status}(LV) = \text{BaseStatus} \times (1 + (LV - 1) \times 0.015)$$
    - 対象: `HP`, `ATK`, `DEF`, `SPD`（※1レベルごとに基礎値の `+1.5%` 増加、Lv.100で約2.5倍に成長）。
    - アイテムカード（`type: 'item'`）はレベル育成の対象外（固定効果）。
    - **全画面即時同期 (Hydration)**: `StorageManager.getDeck()` 経由で取得するデッキ内キャラクター情報は、常に図鑑コレクション（`collection`）の最新成長ステータス（HP/ATK/DEF/SPD/Lv）と完全同期され、ホーム画面表示およびバトル開始時の実能力値に即座に反映される。
  - **既存データ互換性**: 過去バージョンの保存データに対し、`level: 1, exp: 0` を自動補完する安全マイグレーションを実施。
- **受け入れ基準 (DoD)**:
  - [ ] P2P対戦勝利時に出撃キャラクターに+100 EXP、敗北時に+30 EXPが付与され、必要EXP到達時にレベルアップすること。
  - [ ] レベルアップ後のHP/ATK/DEF/SPDが、ホーム画面（メインキャラ展示）およびバトル画面（実際のHPバー・与被ダメージ）に正しく反映されること。
  - [ ] 3P対戦時、戦闘に出撃したキャラクターのみにEXPが付与され、出撃しなかった控えキャラクターには付与されないこと。
  - [ ] レベルアップ時にHP, ATK, DEF, SPDが計算式（+1.5%/Lv）通りに増加し、図鑑およびバトルで反映されること。
  - [ ] CPU対戦では経験値が一切獲得できないこと。
  - [ ] 旧バージョンの既存カードデータが自動でLv.1, EXP:0にマイグレーションされ正常に動作すること。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1 パフォーマンス
- **スキャン解析速度**: カメラフレームからのバーコード検知からカード生成完了まで **1.0秒以内**。
- **UI描画フレームレート**: モバイル端末上で常時 **30fps以上**（推奨 60fps）を維持。
- **初期バンドルロード**: 初回ページロード時間 **2.0秒以内**（WiFi環境）。

### 4.2 オフライン動作 & PWAキャッシュ
- **完全オフライン動作**: ネットワーク接続がない状態でも「カメラ/手動スキャン」「図鑑閲覧」「デッキ編成」「CPU対戦」が100%動作すること。
- **キャッシュ無効化対策**: バージョン更新時の即時反映のため、クエリバージョニング（`?v=3.0.0`）および `no-cache` ヘッダーを適用。

### 4.3 プラットフォーム互換性 & フォールバック
- **対応OS/ブラウザ**: iOS Safari (iOS 15+), Android Chrome (Android 10+), PC Chrome/Edge/Safari。
- **BarcodeDetector 非対応フォールバック**: 手動JAN入力フォームおよびデモ用テストバーコードUIへ自動切り替え。

### 4.4 サウンド & ハプティクス (演出・フィードバック)
- **効果音 (SE)**: スキャン成功音、ガチャカットイン音、攻撃ヒット音、必殺技音、勝敗ジングル、レベルアップファンファーレ。
- **振動フィードバック (Web Vibration API)**: スキャン成功時パルス振動、ダメージ被弾時振動。

|---|---|---|
