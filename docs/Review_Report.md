## 2. 観点別検証結果

### 2.1 曖昧さの排除と具体性 (Acceptance Criteria)
- **ステータス生成**: JAN13コードの各桁を用いた明確な数式が定義されており、同一バーコードからの再現性が担保されている。
- **バトル計算式**: 通常攻撃（乱数 $\pm 10\%$ 補正、MISS率8%）、SPD行動順（乱数 $\pm 15\%$ 補正）、SPゲージ増加条件、QTE（ダメージ2.5倍）などのパラメータ数値が具体的でテスト可能。
- **データ管理**: ローカル保存上限 100 体、メモ欄の存在が明確化されている。

### 2.2 技術的実現可能性 (Feasibility)
- **バーコード解析**: Google ML Kit / ZXing によりクライアントサイドで高速かつオフライン処理が可能。
- **リアルタイム対戦**: WebSocket / Firebase Realtime Database (Free Tier) のP2Pまたは軽量リレイにより、運用費0円かつ2秒以内の同期を実現可能。
- **クロスプラットフォーム**: Unity / Flutter または Web標準技術により、iOS / Android での 30fps 以上動作が容易に達成可能。

### 2.3 エッジケース・例外処理ハンドリング
- **バーコード読み取り不可・不正コード**: 無効なコード読み取り時はエラーサウンドとともに「バーコードが よみとれませんでした」ダイアログを表示。
- **カメラ権限エラー**: 初回非許可時はカメラ権限のリクエストを促す案内画面へ誘導。
- **存在しないルームコード**: ルーム参加時、該当コードが存在しない場合は「へやが つつかりませんでした」と入力リトライを促す。
- **対戦中の通信断・離脱**: バトル中片方の通信が切断した場合、5秒のタイムアウト判定後に「あいての つうしんが きれました」と表示し、勝利判定としてロビーに安全復帰させる。
